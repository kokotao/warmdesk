# WarmDesk 栗子镜像接入调研

## 结论

当前栗子下载镜像已经存在 Tau Editor 专用链路，但尚未发现 WarmDesk 的镜像目录或公开 manifest。WarmDesk 不能直接复用 Tau Editor 的公开路径，否则会把两个产品的版本和资产混在同一份 `latest.json` 中。

建议为 WarmDesk 新增独立镜像前缀：

```text
https://note.lizipro.cn/warmdesk/releases/latest.json
https://note.lizipro.cn/warmdesk/releases/<version>/<asset>
```

镜像同步必须在 GitHub Release 资产下载、文件大小和 SHA-256 校验全部通过后，最后原子发布 `latest.json`。

## 已核验事实

### 现有 Tau Editor 镜像

- 同步脚本：`text-editor/scripts/release-mirror.sh`
- 环境模板：`text-editor/scripts/release-mirror.env.example`
- 公开根 manifest：`https://note.lizipro.cn/taueditor/releases/latest.json`
- 2026-11-10 只读请求返回 HTTP `200`，内容版本为 `0.6.42`。
- 现有同步脚本支持 GitHub Release 下载、缓存命中、SHA-256 校验、版本目录、根目录 `latest.json` 和 SSH/rsync 上传。
- 现有生产路径绑定 `/opt/1panel/www/sites/lizi/index/taueditor/releases`，不能据此证明 WarmDesk 路径已创建。

### WarmDesk 镜像

- `https://note.lizipro.cn/warmdesk/releases/latest.json` 于 2026-11-10 只读请求返回 HTTP `404`。
- 当前没有证据证明 WarmDesk 的服务器目录、1Panel 计划任务、SSH 配置或 Nginx 路由已经部署。
- 本调研没有执行 SSH、rsync、1Panel API 或生产写操作。

## 可复用实现

WarmDesk 可以复制 Tau Editor 的同步逻辑，但必须替换为独立配置：

```text
GITHUB_REPOSITORY=kokotao/warmdesk
NOTE_MIRROR_BASE_URL=https://note.lizipro.cn/warmdesk/releases
NOTE_MIRROR_ROOT=/opt/1panel/www/sites/lizi/index/warmdesk/releases
```

脚本应保留以下门禁：

1. 只接受形如 `vX.Y.Z` 的 tag。
2. 仅处理 `.dmg`、`.zip`、`.msi`、`.exe` 等允许的安装包扩展名。
3. 下载到 `.part` 临时文件，校验文件大小和 SHA-256 后原子改名。
4. 资产全部校验成功后才上传版本目录和 manifest。
5. 远端文件校验成功后最后更新根目录 `latest.json`。
6. 上传失败传播非零退出码，不能让 1Panel 显示假成功。

## 更新入口契约

WarmDesk 更新器应优先请求栗子 manifest，失败时回退 GitHub API 或 Release 下载地址。manifest 使用现有 Tau Editor 兼容结构：

```json
{
  "version": "0.1.0",
  "tag": "v0.1.0",
  "release_url": "https://github.com/kokotao/warmdesk/releases/tag/v0.1.0",
  "generated_at": "2026-11-10T00:00:00Z",
  "assets": [
    {
      "name": "WarmDesk_0.1.0_aarch64.dmg",
      "size": 123,
      "sha256": "…",
      "urls": {
        "note": "https://note.lizipro.cn/warmdesk/releases/0.1.0/WarmDesk_0.1.0_aarch64.dmg",
        "github": "https://github.com/kokotao/warmdesk/releases/download/v0.1.0/WarmDesk_0.1.0_aarch64.dmg"
      }
    }
  ]
}
```

客户端必须只允许 HTTPS URL，下载后再次校验大小与 SHA-256；不能把 `latest` 二进制直接执行或覆盖现有安装。
