# macOS Apple Silicon 温度采集调研

## 结论

本机为 Apple Silicon MacBook Pro（`Mac17,2`，Apple M5，`arm64`，macOS `27.2`）。在不安装第三方软件、不申请管理员权限的前提下，当前没有可稳定依赖的公开 CPU 封装温度接口：

- `powermetrics` 支持 `thermal` sampler，但本机执行明确要求 superuser；WarmDesk 不应在后台强制要求用户输入管理员密码。
- `ioreg -r -c IOHWSensor -l` 在本机无输出；不能把该私有/历史路径当作 Apple Silicon 通用 CPU 温度接口。
- `pmset -g therm` 只能报告 thermal/performance warning 等状态，不返回摄氏温度。
- `system_profiler SPPowerDataType` 和 `pmset -g batt` 可稳定读取电池电量、AC 连接和充电状态，但不是 CPU 温度。
- `ioreg` 的 `AppleSmartBattery` 节点包含电池原始温度字段，但它是电池温度，不应在 UI 中标成 CPU 温度，也不应作为 CPU 过热保护阈值。

因此 WarmDesk 的 macOS 实现应采用“温度不可用但安全可运行”的降级策略：显示“CPU 温度不可用”，使用 CPU 占用、系统 thermal warning、电源、锁屏和固定保守强度上限共同保护；不要伪造温度或把电池温度替代为 CPU 温度。

## 本机验证

### 设备与系统

```text
Darwin ... Darwin Kernel Version 27.2.0 ... RELEASE_ARM64_T8142
hw.model: Mac17,2
hw.optional.arm64: 1
ProductName: macOS
ProductVersion: 27.2
BuildVersion: 26B123
Chip: Apple M5
Total Number of Cores: 10
```

### `powermetrics`

命令：

```bash
powermetrics -n 1 -i 1000 -s cpu_power,thermal
```

结果：

```text
powermetrics must be invoked as the superuser
```

执行 `sudo -n powermetrics ...` 也无法使用，因为当前环境没有预授权 sudo：

```text
sudo: a password is required
```

本机 `man powermetrics` 显示支持的 sampler 包含 `thermal`、`cpu_power`、`battery`，并支持 `-f plist` 输出；但该工具的权限要求使其不适合作为普通桌面应用的默认后台采样方式。若未来提供“高级诊断”按钮，可以由用户主动授权后短时采样，不能把它作为暖手主循环依赖。

### `ioreg`

命令：

```bash
ioreg -r -c IOHWSensor -l
```

结果：无输出。

进一步检查 `ApplePMGRTempUserClient`、`AppleDieTempControllerUserClient`、`AppleTemperatureSensor` 也没有得到可读温度节点。`AppleARMCPU` 节点只暴露 CPU 拓扑/标识信息，没有稳定的摄氏温度属性。

`AppleSmartBattery` 能看到 `BatteryData` 中的原始 `Temperature=3150`，但这是电池节点字段，不是 CPU 封装温度；WarmDesk 不应将其展示为 CPU 温度。

### 电源与系统热状态

```bash
pmset -g batt
```

本机结果摘要：

```text
Now drawing from 'AC Power'
90%; AC attached; not charging
```

```bash
system_profiler SPPowerDataType
```

能返回电池百分比、AC charger connected、wattage 等信息。

```bash
pmset -g therm
```

本机结果摘要：

```text
No thermal warning level has been recorded
No performance warning level has been recorded
No CPU power status has been recorded
```

它适合做状态保护信号，但不提供 CPU 摄氏温度。`pmset -g thermlog` 在本机可能持续等待事件，不应放入同步采样命令；如使用，必须单独进程、超时和可取消。

## 可落地方案

### 方案 A：默认实现，推荐

1. 每 2 秒执行一次 `top -l 2 -n 0 -s 1`，解析 `CPU usage` 行的 idle 百分比，计算系统 busy 百分比。
2. 每 5 秒执行 `pmset -g batt`，解析电池百分比和 `AC Power`/`Battery Power`。
3. 每 5 秒读取轻量 thermal 状态（优先非阻塞接口；不要直接持有 `pmset -g thermlog` 长连接）。
4. 锁屏时立即停止热负载；锁屏检测失败时按“不可确认”处理并暂停。
5. CPU 温度字段固定返回 `None`，UI 显示“CPU 温度不可用”，同时把最大强度限制在保守值（例如 20% 预算），直到用户明确关闭温度保护。

该方案不需要额外软件、不需要管理员权限，适合暖手主循环。

### 方案 B：用户主动诊断

用户点击“读取详细热状态”后，由 Rust 启动一次：

```bash
sudo powermetrics -n 1 -i 1000 -s thermal,cpu_power -f plist
```

要求：

- 必须明确显示需要管理员权限；
- 只运行单次采样，超时 5 秒；
- 不把 sudo 密码写入应用、日志或配置；
- 用户拒绝授权时回到方案 A；
- 诊断结果只作为辅助信息，不用于承诺“暖手温度”。

### 方案 C：第三方传感器工具

可选工具（如 iStat Menus、macOS 温度监控工具或专门的 Apple Silicon 传感器库）通常通过私有接口、SMC/DriverKit 或辅助进程获取更细的传感器数据。代价是额外安装、版本兼容、权限和供应链风险。当前版本不建议捆绑或自动安装；如果以后支持，应设计为用户自愿配置的外部 provider，失败则回到方案 A。

## 暖手安全降级规则

- `cpu_temperature_c == None` 不代表温度正常，只代表没有可读温度。
- 温度不可用时，最高强度降低；不允许开启“无限制”。
- `thermal warning`、CPU 占用持续高于阈值、进入电池低电量、锁屏、睡眠或采样超时，立即停止或降级为低占空比。
- 任何采样命令设置 1.5～3 秒超时；不能让 UI 线程等待系统命令。
- 退出应用、托盘退出和系统注销时，先停止热负载线程，再退出进程。
- UI 文案写“受控 CPU 负载产生机身余热”，不要写“加热到 XX°C”或“保证暖手”。
