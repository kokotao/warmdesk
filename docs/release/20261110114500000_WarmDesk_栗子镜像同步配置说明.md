# WarmDesk 栗子镜像同步配置说明

## 仓库侧入口

镜像同步 workflow 为 `.github/workflows/release-mirror.yml`。

- `Release` workflow 成功完成后自动触发。
- `workflow_dispatch` 可手动指定已有 tag。
- 手动执行默认 `dry_run=true`，只下载公开 GitHub Release 资产、校验并生成 manifest，不执行 SSH/rsync。
- 只有显式将 `dry_run` 设为 `false` 并配置完整 Secrets 后，才会写入栗子镜像。

## GitHub Actions Secrets

在 `kokotao/warmdesk` 仓库配置以下 Secrets：

| Secret | 用途 |
| --- | --- |
| `WARM_DESK_MIRROR_SSH_KEY` | 仅用于镜像主机的 SSH 私钥 |
| `WARM_DESK_MIRROR_HOST` | `user@host` 形式的 SSH 目标 |
| `WARM_DESK_MIRROR_ROOT` | 远端目录，例如 `/opt/1panel/www/sites/lizi/index/warmdesk/releases` |
| `WARM_DESK_MIRROR_BASE_URL` | HTTPS 公网前缀，默认 `https://note.lizipro.cn/warmdesk/releases` |

工作流不会把 Secrets 写入仓库文件。SSH 使用临时 runner 配置，任务结束后随 runner 销毁。

## 同步门禁

`scripts/release-mirror.sh` 会：

1. 校验 `vX.Y.Z` 版本 tag。
2. 要求对应 GitHub Release 已发布、非 draft、非 prerelease，并且 tag 完全匹配。
3. 从 GitHub Release 读取允许的 `.dmg`、`.zip`、`.msi`、`.exe` 资产，并校验下载地址属于对应 GitHub Release。
4. 先写 `.part` 文件，再校验大小和 SHA-256 后原子改名。
5. 生成与 Tau Editor 兼容的 `latest.json`。
6. 仅接受 HTTPS 镜像基础 URL。
7. 远端资产校验通过后才发布版本 manifest，根目录 `latest.json` 最后更新。

## 当前状态

仓库侧同步链路已准备，但没有执行生产 SSH/rsync，也没有声称公网 WarmDesk 镜像已上线。首次正式同步前应先执行一次手动 dry-run，再由主控在具备服务器凭据后执行正式同步并验证：

```bash
curl -fsS https://note.lizipro.cn/warmdesk/releases/latest.json | jq .
```
