# 暖桌面（WarmDesk）跨平台产品规格

## 1. 产品定位

暖桌面是一款运行在 macOS 与 Windows 的轻量桌面工具，通过受控的 CPU 低占用工作负载提供温和、可调节的机身余温，帮助用户在冬季使用电脑时保持手部舒适。

产品默认优先保证电脑可用性：任何时候都允许一键停止；在温度、系统负载、电量或用户活动异常时自动降载或暂停。产品不以“跑满硬件”为目标，也不承诺把整台电脑加热到固定温度。

## 2. 目标与非目标

### 2.1 目标

- 支持 macOS 11+ 与 Windows 10/11。
- 提供低、中、高三档与自定义强度。
- 提供持续运行、倒计时、定时停止三种运行方式。
- 提供“轻柔 / 平衡 / 暖手”预设，方便非技术用户直接使用。
- 显示当前运行状态、预计占用、运行时长及保护状态。
- 用户关闭窗口后可继续托盘运行，并能从托盘快速暂停。
- 在不依赖管理员权限的情况下完成基础功能。

### 2.2 非目标

- 不修改 CPU/GPU 倍频、电压、风扇曲线或系统电源计划。
- 不绕过操作系统的温控与降频保护。
- 不保证机身外壳某个位置达到指定温度。
- 不在电池极低、系统过热或用户明确暂停时继续运行。
- 不通过后台挖矿、网络请求或不可见进程维持负载。

## 3. 视觉定位

- 气质：温暖但克制，像冬季桌面上的实用小工具，不做拟物暖炉或夸张发光效果。
- 背景使用偏浅的中性色，搭配暖橙色作为运行状态强调色；错误与过热状态使用清晰的红色，安全状态不单靠颜色表达。
- 运行状态优先使用明确文字与简洁温度/负载指标，不使用持续闪烁、粒子或高频动画。
- 信息密度适中，控件始终可见；主操作和强度设置不藏在二级设置页。
- 深色模式跟随系统，保持同一套颜色语义和对比度。

## 4. 内容结构

主界面按任务顺序展示：

1. 当前状态与主操作。
2. 暖手强度与预设。
3. 运行时长与停止计划。
4. 温度、负载、电源等保护信息。
5. 简短运行统计与设置入口。

设置页只放低频配置：启动行为、托盘行为、外观、保护档位、日志清理与隐私说明。保护触发原因应出现在主界面，不要求用户去设置页寻找。

## 5. 交互反馈

- 开始后主按钮即时切换为“暂停”，同时显示“正在启动…”短暂过渡态；只有后台控制器确认工作线程启动后才标记为运行中。
- 暂停/停止立即更新按钮状态，并在控制器确认取消后显示“已暂停”或“已停止”。
- 修改强度时，文字档位和上限数值即时变化；工作预算平滑过渡，避免突然跳升。
- 自动降载以非阻塞提示说明原因，例如“系统负载较高，已降至轻柔”；保护暂停时使用醒目的持久状态条，直到用户确认或条件恢复。
- 温度不可读时展示“温度不可读，强度已受限”，不显示虚构读数。
- 倒计时开始、到期和保护暂停通过轻量状态提示反馈；不使用声音作为默认反馈。
- 按钮有 hover、pressed、focus-visible、disabled 状态；自动暂停状态须能通过屏幕阅读器播报。

## 6. 核心交互

### 6.1 主窗口

主窗口采用单页控制面板，默认尺寸约 420 x 560 px，信息层级从上到下为：

1. **当前状态**
   - 状态标签：已停止 / 运行中 / 自动降载 / 已暂停。
   - 主状态按钮：开始暖手 / 暂停 / 继续。
   - 主按钮必须有键盘焦点样式，并支持 `Space` 快捷切换。
2. **暖手强度**
   - 分段控制：轻柔、平衡、暖手、自定义。
   - 自定义模式使用 0-100 滑杆，步进 5；默认上限 60。
   - 滑杆旁显示“预计 CPU 占用上限”，使用区间而非伪精确值。
3. **运行方式**
   - 持续运行。
   - 倒计时：15 / 30 / 60 / 120 分钟或自定义。
   - 定时停止：选择结束时间，跨午夜时显示完整日期。
4. **保护设置**
   - 温度保护：默认开启且不可关闭，只能调整保护阈值档位。
   - 电池保护：电池模式下默认限制为轻柔；可选“插电才运行”。
   - 空闲降载：检测到用户正在运行游戏、视频导出或高负载任务时自动降低强度。
5. **运行统计**
   - 已运行时长。
   - 当前负载档位。
   - 保护事件数量。
   - 最近一次自动降载原因。

### 6.2 托盘 / 菜单栏

- 显示当前状态和强度。
- 提供开始、暂停、恢复、停止。
- 提供“打开主窗口”和“退出应用”。
- 退出动作必须真正终止负载线程，不允许只隐藏窗口。

### 6.3 首次启动提示

首次启动用一个非阻塞提示说明：

> 暖桌面通过受控的低占用计算提供余温。它不会修改硬件参数；当系统温度、负载或电量不适合继续运行时，会自动降载或暂停。

不使用强制确认弹窗阻塞用户，但“开始暖手”前应展示默认保护已开启。

## 7. 强度模型

### 7.1 设计原则

强度不是“CPU 百分比锁定”，而是应用内部工作预算。运行时按时间片工作，并在每个周期释放 CPU，让操作系统和其他应用获得调度机会。

### 7.2 推荐档位

| 档位 | 工作预算 | 默认 CPU 目标上限 | 适用场景 |
|---|---:|---:|---|
| 轻柔 | 10% | 约 8-12% | 打字、阅读、会议 |
| 平衡 | 25% | 约 18-25% | 日常办公 |
| 暖手 | 40% | 约 28-40% | 桌面空闲或轻办公 |
| 自定义 | 5%-60% | 不高于 60% | 熟悉设备状态的用户 |

CPU 目标上限仅作为控制目标，实际占用随核心数、调度器、温控和其他进程变化。实现不得以忙等循环永久占满核心。

### 7.3 工作循环

- 基础周期：100 ms。
- 在周期内按预算计算工作片段与休眠片段。
- 每 1 秒重新采样一次系统状态。
- 当检测到前台应用输入、CPU 总占用、温度或电量变化时，立即重新计算预算。
- 所有工作线程均应支持取消令牌，暂停或退出后 500 ms 内停止新任务。

## 8. 自适应与安全上限

### 8.1 温度保护

- 默认开启，不允许关闭。
- 若平台可读取 CPU 温度，则以 CPU Package / Tctl / SoC 等可用传感器的最高有效值作为参考。
- 建议保护档位：
  - 保守：达到 65°C 开始降载，达到 75°C 暂停。
  - 平衡（默认）：达到 75°C 开始降载，达到 85°C 暂停。
  - 宽松：达到 82°C 开始降载，达到 92°C 暂停。
- 传感器不可用时不得假装有温度数据；界面显示“温度不可读”，并将最高强度限制为轻柔或平衡。
- 温度连续 30 秒低于恢复阈值后，允许逐档恢复；不得瞬间跳回用户设定的最高强度。

### 8.2 系统负载保护

- 系统 CPU 总占用超过 70% 时，暖桌面不再增加工作量。
- 超过 85% 时自动降到轻柔。
- 超过 95% 时暂停并提示“系统正在处理高负载任务”。
- 采样使用 3 秒滑动平均，避免短暂峰值造成抖动。

### 8.3 电源与电池

- 电池电量低于 20% 时自动降到轻柔。
- 电池电量低于 10% 时暂停。
- “仅插电运行”开启时，检测到电池供电立即暂停。
- macOS 与 Windows 均显示电源来源；读取失败时采取保守策略，不提升强度。

### 8.4 设备休眠与锁屏

- 锁屏后默认继续运行，但强度降为轻柔。
- 进入系统睡眠、休眠或关机前必须停止工作线程。
- 用户回到桌面后不自动恢复高强度，先保持暂停，需用户明确恢复。

## 9. 定时、暂停与恢复

- 暂停是幂等操作，重复点击不产生副作用。
- 倒计时剩余 5 分钟时显示轻提示，不弹出强打断窗口。
- 倒计时结束后进入“已完成”状态，负载停止但应用保留在托盘。
- 自动保护暂停后，显示原因和恢复条件；用户不能绕过正在生效的硬保护。
- 应用重启后默认恢复“已停止”，不自动恢复之前的高强度任务。
- 退出应用时必须等待工作线程确认停止，再结束进程；超时 2 秒则强制终止并记录本地日志。

## 10. 数据与隐私

- 默认只保存本地设置：上次档位、倒计时偏好、保护档位。
- 不上传硬件信息、应用列表、温度或运行统计。
- 日志只记录时间、状态转换、保护原因和错误码，不记录窗口标题或用户文件内容。
- 用户可在设置中一键清除本地运行记录。

## 11. 验收标准

### 功能验收

- macOS 与 Windows 均可启动、暂停、恢复、停止。
- 三档预设与自定义滑杆生效，调整后 2 秒内反映在工作预算。
- 倒计时结束自动停止；退出应用后进程无残留。
- 托盘菜单能完成开始、暂停、停止和退出。
- 温度/负载/电量保护触发后，状态和原因可见。

### 性能验收

- 轻柔档下，应用自身 CPU 平均占用目标不超过 12%。
- 平衡档下，应用自身 CPU 平均占用目标不超过 25%。
- 空闲状态内存目标不超过 120 MB。
- 暂停后 1 秒内 CPU 占用回落到接近 0%。
- 主线程无持续阻塞，拖动滑杆、切换窗口和输入操作保持可用。

### 安全验收

- 不存在修改电压、倍频、风扇策略或系统电源策略的代码路径。
- 传感器不可读时自动采用保守限制。
- 高系统负载、低电量、睡眠前均能自动降载或停止。
- 任何状态均可通过主按钮或托盘在 1 次操作内停止。

## 12. 实现建议

- 桌面壳使用 Tauri 2，前端使用 Vue 3 + TypeScript。
- 负载控制放在 Rust 后端线程，避免 JavaScript 定时器被后台节流后失控。
- 平台能力抽象为 `SystemMonitor`：CPU 总负载、电源状态、温度（可选）、锁屏/睡眠事件。
- 运行控制抽象为 `HeatController`：预算计算、工作片段、取消、状态机和保护策略。
- 将平台不可用能力以 `Unavailable` 明确返回，禁止使用猜测值。
- 首个版本可先实现 CPU 低占用工作预算与电源/系统负载保护；温度读取按平台能力逐步补齐。
