# WarmDesk 真实暖手功能实现设计

## 1. 目标与边界

WarmDesk 的暖手效果来自受控 CPU 工作负载带来的设备余热。它不是加热器，也不能直接控制键盘、掌托或手部温度。不同电脑的散热路径、风扇曲线、环境温度和电源状态不同，因此产品只承诺：

- 在安全预算内持续产生可感知但不可保证的设备余热。
- 工作负载可调、可暂停、可取消，退出应用时不留后台任务。
- 任何保护条件触发时自动降载或停止。
- 不能修改 CPU/GPU 电压、倍频、风扇曲线或操作系统电源策略。

温度传感器不可用时不显示估算温度；UI 必须显示“温度不可读，已启用保守上限”。

## 2. 系统分层

```text
Vue UI
  └─ Tauri invoke 命令
       └─ HeatController（单例）
            ├─ Worker：可取消 CPU 工作片段
            ├─ SafetyPolicy：温度/负载/电源/锁屏状态机
            └─ SystemMonitor：macOS/Windows 平台采样
```

`HeatController` 是唯一允许启动工作线程的模块。UI 不直接创建定时器或计算循环；所有状态由 Rust 控制器返回，避免窗口隐藏、后台节流或前端崩溃后负载失控。

## 3. 强度与工作节奏

### 3.1 用户强度

前端传入 `intensity`，取值 5-60。它是工作预算百分比，不是系统 CPU 锁定值：

| 强度 | 预算占比 | 默认用途 |
| ---: | ---: | --- |
| 5-15 | 轻柔 | 打字、会议、视频 |
| 16-30 | 平衡 | 日常办公 |
| 31-45 | 暖手 | 桌面空闲或轻办公 |
| 46-60 | 自定义上限 | 仅熟悉设备状态的用户 |

首次启动默认 25；传感器不可用或电池供电时最高 25；低电量时最高 15。

### 3.2 分时循环

- 基础周期为 100 ms。
- 每周期先执行工作片段，再休眠剩余时间；禁止无休止忙等。
- 根据当前有效预算计算工作片段：`work_ms = clamp(100 * budget / 100, 5, 60)`。
- 工作片段结束后使用可中断休眠，最长 95 ms。
- 每 1 秒采样一次系统状态，每次采样都重新计算有效预算。
- 预算变化使用 2 秒线性过渡，避免拖动滑杆时瞬间跳升。
- 取消令牌在每个片段边界检查；暂停、停止或退出后 500 ms 内不再开始新片段。

工作内容使用确定性的内存内整数运算，禁止网络请求、文件扫描、挖矿算法或大块内存分配。工作线程优先级保持系统默认，不设置实时优先级。

## 4. 模式

- `steady`：按有效预算持续运行，适合长时间办公。
- `pulse`：100 ms 周期内工作片段缩短、休眠片段加长，降低持续风扇声，热感更温和。
- `adaptive`：根据系统负载、电源、锁屏和温度保护动态选择预算；用户档位只作为上限。

模式不是安全保护的替代品。任何模式都必须经过 `SafetyPolicy` 限制。

## 5. 保护状态机

### 5.1 状态

- `stopped`：无工作线程。
- `starting`：已接受启动请求，正在创建线程。
- `running`：按有效预算工作。
- `throttled`：仍运行，但有效预算低于用户请求。
- `paused`：由用户或保护条件暂停。
- `completed`：倒计时完成后停止，保留统计。
- `error`：启动或采样出现不可恢复错误，工作线程已停止。

### 5.2 保护优先级

`退出/睡眠 > 过热 > 极低电量 > 系统高负载 > 锁屏 > 传感器不可用 > 用户强度`

建议阈值：

- 系统 CPU 平均占用 `>=95%`：暂停。
- 系统 CPU 平均占用 `>=85%`：有效预算不超过轻柔。
- 电池 `<=10%`：暂停；`<=20%`：有效预算不超过轻柔。
- 仅插电运行开启且当前不在交流电：暂停。
- 锁屏：有效预算不超过轻柔；解锁后保持暂停，需用户点击继续。
- 温度 `>=暂停阈值`：暂停；达到降载阈值：逐级降低预算。默认降载/暂停阈值为 75°C / 85°C。
- 温度不可读：不阻止轻柔运行，但最高强度限制为 25，UI 显示限制原因。

温度连续 30 秒低于恢复阈值后，只允许每 10 秒恢复一个档位；解锁、睡眠恢复和高负载解除后不自动恢复到用户原始高强度。

## 6. 采样契约

Rust 平台模块每秒返回：

```rust
pub struct MonitorSnapshot {
    pub cpu_usage_percent: Option<f32>,
    pub cpu_temperature_c: Option<f32>,
    pub battery_percent: Option<u8>,
    pub on_ac_power: Option<bool>,
    pub locked: bool,
    pub note: Option<String>,
}
```

字段不可用时使用 `None`，不能使用 0、-1 或历史值冒充当前读数。系统命令必须有超时；权限不足、无传感器和平台不支持都转换为可展示的 `note`，不能 panic。

## 7. Tauri 命令契约

### `get_warm_status`

返回当前控制器状态：

```json
{
  "state": "running",
  "running": true,
  "requested_intensity": 30,
  "effective_intensity": 24,
  "mode": "adaptive",
  "elapsed_seconds": 128,
  "remaining_seconds": 1672,
  "cpu_usage_percent": 18.4,
  "cpu_temperature_c": null,
  "battery_percent": 86,
  "on_ac_power": true,
  "locked": false,
  "protection_reason": "温度不可读，已启用保守上限",
  "monitor_note": "temperature_unavailable"
}
```

### `start_warming`

请求体：

```json
{
  "intensity": 30,
  "mode": "steady",
  "duration_minutes": 60
}
```

行为：验证范围、创建或复用控制器、执行安全策略后启动工作线程。重复调用是幂等的；运行中只更新请求预算，不创建第二个线程。

### `stop_warming`

设置取消令牌并等待线程退出，返回停止后的状态。必须在 2 秒内完成；超时记录错误并继续清理资源。

### `pause_warming` / `resume_warming`

用户暂停是幂等的。保护暂停不能被 `resume` 绕过，只有采样条件恢复后才允许继续。

### `set_theme`

接受 `light`、`dark`、`system`，只保存本地偏好，不影响控制器。

## 8. 错误码

- `invalid_intensity`：强度超出 5-60。
- `already_stopped`：停止命令重复调用，不视为失败。
- `protected_overheat`：温度达到暂停阈值。
- `protected_high_load`：系统负载过高。
- `protected_low_battery`：电量过低。
- `protected_ac_required`：当前非交流电。
- `monitor_unavailable`：采样不可用，已使用保守上限。
- `worker_start_failed`：线程创建失败。
- `worker_stop_timeout`：停止等待超过 2 秒。

## 9. 退出、睡眠和崩溃策略

- Tauri `RunEvent::Exit`、窗口关闭退出和托盘退出都必须调用同一个 `stop_warming` 清理路径。
- 睡眠/休眠前取消工作线程；恢复后状态为 `paused`，不自动提高强度。
- 控制器只持有线程句柄、取消令牌和原子状态；不把任务放入无法回收的全局线程池。
- 应用重启后默认 `stopped`，不恢复上次运行任务。

## 10. 验收指标

- 轻柔档应用自身平均 CPU 占用目标不超过 12%，平衡档不超过 25%。
- 暂停或停止后 1 秒内应用 CPU 占用回落到接近 0%。
- 取消响应 P95 不超过 500 ms，退出清理 P99 不超过 2 秒。
- 滑杆调整在 2 秒内反映到有效预算。
- 传感器不可读时 UI 显示限制原因，不显示假温度。
- 高负载、低电量、锁屏、退出路径均有可观察的状态转移和测试覆盖。
- macOS 和 Windows 均完成编译；平台不可用能力必须在 UI 与日志中可见。

## 11. 回滚与降级

若任一平台采样或托盘能力导致构建失败，保留 `HeatController` 和 `SystemMonitor` 抽象，使用 `Unavailable` 适配器降级到轻柔上限；不得退回无保护的模拟忙循环。若发现实际设备温升或风扇噪音明显超出预期，优先将默认强度降至 15 并发布配置级回滚。
